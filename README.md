# «Тепло простих розмов» — музичне привітання для Віти

Персональний сайт-привітання з Днем Вчителя від Сергія. Під час відтворення готової пісні двоє анімованих персонажів розігрують маленьку історію за мотивами рядків, а в нижній частині кадру проявляються саме ті слова, які зараз звучать.

- Стек: **React + TypeScript + Vite**, багатошарові SVG-ілюстрації, власна детермінована система анімації (одна, без сторонніх анімаційних бібліотек).
- Єдине джерело часу для сцен, поз персонажів і субтитрів — `audio.currentTime`.
- Сайт статичний: без бекенду, бази даних, платних API, аналітики й відстеження. Пісня — локальний файл у самому сайті.

---

## Швидкий старт

Потрібен Node.js 20.19+ або 22.12+ (перевірено на Node 24).

```bash
npm install
npm run dev
```

Відкрийте адресу, яку покаже Vite (зазвичай http://127.0.0.1:5173/).

| Команда | Що робить |
|---|---|
| `npm run dev` | локальна розробка |
| `npm run typecheck` | перевірка TypeScript |
| `npm run build` | production-збірка у `dist/` з відносними шляхами (`./`) — працює в будь-якій папці хостингу |
| `npm run build:pages` | збірка з базовим шляхом GitHub Pages `/vita-teacher-day/` |
| `npm run preview:pages` | перегляд цієї збірки за адресою http://127.0.0.1:4173/vita-teacher-day/ |

## Де лежить пісня

- Файл, який використовує сайт: **`public/audio/vita-teacher-day.mp3`** (точна копія вашого `Тепло простих розмов_01.mp3`, перевірено SHA-256).
- Шлях задано в `src/config/site.ts` (`audioFile`). Щоб замінити запис, покладіть новий файл з тією ж назвою або змініть `audioFile`.
- Оригінал із кириличною назвою в корені проєкту виключено з git (`.gitignore`), щоб не публікувати один файл двічі.

## Тексти й налаштування

- `src/config/site.ts` — ім’я, підпис, тексти першого й фінального екранів, назва історії, шлях до аудіо.
- `src/data/lyrics.ts` — текст пісні звичайним правописом, ідентифікатори рядків (повторні приспіви мають окремі: `c1-*`, `c2-*`, `f-*`), групування субтитрів по 1–2 рядки.
- `src/data/timing.json` — **таймкоди секцій і рядків** (окремі початок і кінець для кожного рядка).
- `src/story/SceneTimeline.ts` — розклад сцен і загальних подій (святковий напис, фінальний напис), прив’язаний до рядків.
- Ключові дії персонажів — у файлах сцен `src/scenes/*Scene.tsx` (функція `plan`), теж прив’язані до рядків: якщо уточнити таймкоди, режисура зсунеться разом із ними.

## Таймкоди: як було розмічено і як уточнити

**Статус: чернетка (`"status": "draft"`, кожен рядок `"status": "auto"`).**

Розмітку зроблено автоматично й локально (запис нікуди не надсилався):
1. Локальне розпізнавання Whisper (моделі `small` і `large-v3-turbo`, пословні мітки часу) — текст пісні розпізнано майже дослівно, структура запису така: вступ 0–12 с, куплет 1, приспів 1 (≈50,5 с), куплет 2 (≈72 с), приспів 2 (≈110,5 с), **інструментальний програш ≈129–149 с**, брідж, фінальний приспів (≈170,4 с), кода «З Днем Вчителя, Віта… Хай тобі буде тепло» (≈192–200 с) і **інструментальне завершення до 3:43**.
2. Початки рядків, які Whisper «приклеював» до попередньої паузи, уточнено вручну за спектрограмою і за повторюваністю приспівів (період ≈59,94 с).

03.10.2026 користувач прослухав пісню на сайті й підтвердив повну відповідність тексту запису. Наявні таймкоди та індивідуальні статуси рядків збережено. Якщо надалі потрібно змінити розмітку, скористайтеся вбудованим редактором:

1. `npm run dev`
2. Відкрийте **http://127.0.0.1:5173/?dev=calibrate**
3. Праворуч — список усіх 34 рядків. Слухайте пісню і:
   - `S` — початок вибраного рядка = поточний час, `E` — кінець;
   - `N` — кінець поточного й початок наступного (зручно «проходити» пісню підряд);
   - `P` — програти вибраний рядок з −1 с; `↑/↓` — вибір рядка; пробіл — пауза;
   - числа можна правити вручну; кнопки ⏱ ставлять поточний час.
4. Позначте перевірені рядки галочкою «на слух».
5. **«Зберегти у проєкт»** записує результат у `src/data/timing.json` (працює тільки на dev-сервері). Також є **«Експорт JSON»** / **«Імпорт JSON»**.
6. Зміни застосовуються наживо: субтитри, сцени й дії персонажів одразу переміщуються.

Редактор існує лише в режимі `npm run dev` і в production-збірку не потрапляє (перевірено пошуком у `dist/`).

Інші dev-параметри: `?dev=hud` (час, сцена, рядок у кутку), `?t=95` (одразу перейти до 1:35 на паузі), `?reduced=1` (примусово режим зменшеного руху), `?dev=lab` (лабораторія персонажів).

## Публікація на GitHub Pages

Сайт уже налаштований для GitHub Pages: базовий шлях підставляється автоматично з налаштувань Pages, а workflow `.github/workflows/deploy.yml` встановлює залежності, збирає Vite-проєкт, завантажує `dist` і публікує його.

### 1. Створіть репозиторій
На github.com → **New repository** → назва, наприклад, **`vita-teacher-day`** → Public (для безкоштовних Pages) → **Create repository** (без README, .gitignore і ліцензії — вони вже є).

### 2. Завантажте файли
У папці проєкту:

```bash
git init -b main
```
```bash
git add .
```
```bash
git commit -m "Музичне привітання для Віти"
```
```bash
git remote add origin https://github.com/USERNAME/vita-teacher-day.git
```
```bash
git push -u origin main
```

Публікуються: `index.html`, `package.json`, `package-lock.json`, `tsconfig*.json`, `vite.config.ts`, `tools/`, `src/`, `public/` (разом із `public/audio/vita-teacher-day.mp3`, ≈8,9 МБ), `.github/workflows/deploy.yml`, `.gitignore`, `README.md`.
Не публікуються (виключено в `.gitignore`): `node_modules/`, `dist/`, оригінальний mp3 із кириличною назвою, локальні налаштування.

### 3. Увімкніть GitHub Pages
Репозиторій → **Settings → Pages → Build and deployment → Source: «GitHub Actions»**.

### 4. Запустіть публікацію
- Автоматично: кожен `git push` у гілку `main`.
- Вручну: вкладка **Actions → «Deploy to GitHub Pages» → Run workflow**.

Через 1–2 хвилини у вкладці Actions з’явиться зелена позначка і посилання.

### 5. Адреса сайту
**`https://USERNAME.github.io/vita-teacher-day/`** (якщо назвати репозиторій інакше — `https://USERNAME.github.io/НАЗВА/`; для репозиторію `USERNAME.github.io` — корінь `https://USERNAME.github.io/`).

### Інший хостинг
`npm run build` створює `dist/` з відносними шляхами — цю папку можна покласти в корінь домену або в будь-яку підпапку. Для конкретного абсолютного шляху: `npx vite build --base /моя-папка/`.

## Режисура (за фактичним записом)

| Фрагмент | Що відбувається |
|---|---|
| Вступ 0–12 с | Альбом на столі в сонячних смугах; обкладинка відкривається, з’являється назва «Тепло простих розмов»; камера наїжджає в ілюстрацію шкільного вікна, яка стає справжнім вікном класу |
| Куплет 1, рядки 1–4 | Клас: біля вікна з книгою, листопад; сміх у коридорі — світло з дверей, вона обертається до класу; розгортає книгу; відкритий жест, крейдяні малюнки «оживають» |
| Куплет 1, рядки 5–8 | Збіжний наплив клас → її кімната; відкладає зошити, вмикає теплу лампу, сідає в крісло, бере чашку чаю, заплющує очі; дивиться на дитячі листівки «Дякуємо!» |
| Приспів 1 | Світло лампи переходить у золоте подвір’я школи; він підходить і дарує невеликий букет, вона приймає (передача з рук у руки), світло теплішає, квіти розкриваються, з’являється напис |
| Куплет 2 | Дві кімнати, розмова телефоном; тепла нитка світла між телефонами; іскорки біжать від того, хто говорить, до того, хто слухає; «успіх» — радісний жест, «невдача» — коротка зміна настрою і підтримка, потім ролі міняються; годинники біжать, за вікнами хмаринки й ніч; обидві кімнати набувають спорідненого світла |
| Приспів 2 | Інший ракурс: вечірня вулиця, два вікна навпроти; він піднімає чашку, вона ставить букет на підвіконня; її будинок наповнюється «сонячним» світлом |
| Програш | Осіння алея: вона йде з одного боку, він — з іншого; помічають одне одного |
| Брідж | Однакові кроки назустріч; разом ідуть до тераси; сідають на лавку з природною відстанню; дві чашки на столику, пара м’яко сплітається |
| Фінальний приспів | Тераса в золотому світлі з гірляндою і квітами; легкий «тост» чашками; напис у новій композиції |
| Завершення | «Хай тобі буде тепло» — рух заспокоюється; фінальний напис; після кінця запису — підпис і кнопка «Послухати ще раз» |

## Вимоги → реалізація

| Вимога | Як реалізовано |
|---|---|
| Час — тільки `audio.currentTime` | `AudioPlayer.time()` згладжує лише між оновленнями `currentTime` і постійно до нього підтягується; немає `setTimeout`-сюжету чи незалежного годинника |
| Стан із часу, а не з колбеків | `Track.eval(t)` / `Actor.pose(t)` будують позу з нуля для будь-якого t → після перемотування персонажі одразу в правильних позах |
| Пауза зупиняє анімацію | на паузі цикл rAF зупиняється, кадр перераховується лише на події |
| Повернення у вкладку | `visibilitychange` → кадр за актуальним часом аудіо |
| Повтор скидає історію | `restart()` = перемотати на 0 + відтворити; усе обчислюється від t |
| Окремі дані | секції й рядки — `timing.json`; сцени — `SceneTimeline.ts`; дії — `plan()` сцен |
| Субтитри 1–2 рядки, без накладання | `lyricFrame()` розводить сусідні блоки; блок повністю видимий до співу; без пословної імітації |
| Читабельність | Lora 19–31 px, кремовий текст, м’яка тінь, градієнт знизу без панелі; нерозривні пробіли після коротких слів |
| Без службових написів | «Куплет», «Програш» тощо — лише в даних і dev-панелі |
| Кнопка «Сховати слова» / «Показати слова» | у плеєрі, не зупиняє музику |
| Зменшений рух | ключові композиції змінюються з рядками, камера без руху, субтитри без підняття й світіння |
| Мобільна версія | окремі вертикальні композиції; у розмові кімнати одна над одною; кнопки ≥ 44×44 px; безпечна зона знизу |
| Клавіатура | пробіл/K — пауза, ←/→ — ±5 с, M — звук, L — слова; видимий фокус |
| GitHub Pages | базовий шлях з `configure-pages`, workflow збирає й публікує `dist` |
| Приватність | без аналітики, cookies, зовнішніх запитів; `noindex`, `no-referrer` |
| Делікатність | без освідчень, обручок, поцілунків і обіймів; романтика — через погляди, усмішки, жести підтримки; в усіх зверненнях «Віта» (форми «Віто» в проєкті немає) |
| Символіка | у візуалі немає п’ятикутних зірок чи інших заборонених символів: кленове листя з гострими кінцями свідомо замінено овальним (липа, береза, дуб, каштан), на шпалерах — ромби й крапки, на дошці — сонце-коло, листя, ромашка |

## Що перевірено

- 03.10.2026 виправлено накладання караоке на персонажів на низьких горизонтальних екранах: камера враховує всю висоту текстового блока, керування вміщується в один ряд із кнопками від 44×44 px. Перевірено 667×375, 568×320 та повернення до 390×844. У вікні повного тексту залишено одну прокрутку зі сталим заголовком і кнопкою закриття.
- `npm run typecheck` і `npm run build` / `npm run build:pages` — без помилок.
- Production-збірка з базою `/vita-teacher-day/` відкрита у браузері: JS, CSS, усі шрифти з кирилицею й mp3 завантажуються (mp3 віддається з `206 Partial Content`), dev-коду в збірці немає.
- У вбудованому браузері (звук вимкнено): старт кнопкою, відтворення, пауза (кадр і час не змінюються), перемотування вперед і назад (сцена й рядки одразу відповідають новому часу), завершення запису → фінальний екран, «Послухати ще раз» → історія з початку, «Сховати слова», вікно «Текст пісні» (закривається Esc), режим зменшеного руху, редактор таймкодів.
- Огляд ключових кадрів на 1440×900, 768×1024 і 390×844.
- Вартість оновлення кадру (JS + DOM) на старому Intel i5-3570K — 0,5–1,5 мс.

## Що НЕ перевірено (чесно)

- Плавність малювання (FPS) на реальних телефонах — заміряна лише вартість JS; малювання SVG залежить від пристрою.
- Реальні iOS Safari / Android Chrome — перевірялося в емуляції розмірів екрана.
- Публікацію на GitHub не виконано (за вашою вимогою — лише підготовлено).
